## 7. Business rules (server is the authority)
- net_weight = gross_weight - load.tare_weight * quantity. It must be > 0, otherwise 400 with a field error on the weight. gross_weight > 0, quantity >= 0, rate >= 0.
- line_total = round_half_up(net_weight * rate) as an integer (Decimal with ROUND_HALF_UP).
- Sale.total_amount = sum(line_total) + porterage.amount. Implement ONE service function that recalculates everything, called inside the same transaction after every mutation.
- summary: total = total_amount, paid = sum of payments, accounted = invoice.buyer_amount, remaining = total - paid - accounted.
- Porterage is based on GROSS weight and is incremental. On a line change: delta = round_half_up(change_in_gross * settings.rate_per_kg), where adding a line gives +gross, deleting gives -gross, and editing gives new_gross - old_gross (no change when only quantity or rate changed). new_amount = max(0, old_amount + delta). If settings.round_enabled, new_amount = round_porterage(new_amount). If works_with_porters is False, never change the amount. PUT /sales/{id}/porterage/ {amount} stores the given amount exactly (integer >= 0, no rounding) and it becomes the base for later deltas.

- round_porterage(a): if a <= 0 return 0; r = floor((a + step/2) / step) * step; if r == 0 return step. Examples: 120000 -> 100000, 126000 -> 150000, 125000 -> 150000, 20000 -> 50000.
- Any mutation of a sale that is not a draft (lines, payments, porterage, account) first flips it back to draft (status=draft, finalized_at=NULL) in the same transaction, and the response shows status "draft".
- Finalize: requires at least one line (else 409 code "no_lines") and remaining == 0 (else 409 code "not_settled" and the body also contains "remaining"). On success status = "credit" when invoice.buyer_amount > 0, otherwise "final", and finalized_at = now. Finalizing an already finalized sale returns 200 and changes nothing.
- Adding a line on, or moving a line to, a load that is finished (finished_at not null) -> 409 code "load_finished". Several lines on the same load are allowed. Existing lines on a load that was finished later are untouched.
- Account (the single party who owes or is owed): PUT /sales/{id}/account/ {party, amount} where amount is a non-zero signed integer (positive means the party owes us, negative means we owe the party). It sets invoice.buyer and buyer_amount. DELETE clears them (buyer NULL, amount 0).
- Every mutation takes a lock on the sale row (select_for_update inside transaction.atomic) to serialize concurrent edits.
- Deleting a sale (top-level DELETE) is allowed only for drafts, otherwise 409 code "not_deletable"; it cascades to invoice, lines, porterage and payments.
